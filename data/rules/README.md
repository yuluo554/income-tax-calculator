# data/rules 年度规则包

年度版本化规则集（FR-6）：**切换年度即切换规则**。schema 定稿见 [plan/04 §一](../../plan/04-模块详设.md)。

## 生成与冻结纪律

1. **本目录全部 JSON 为生成器冻结产物，禁止手改**：由 `tools/gen_rulesets.py` 固定模板生成（确定性输出，位级可复现）；改动需求 → 改生成器后整目录重新生成并提交。守门测试 `tests/test_gen_rulesets.py::test_regeneration_byte_identical` 逐字节比对拦截手改漂移；
2. 每个数值条目（含 `value` 键的节点）必带 `ref`（来源文号 + 条款）；`status` 缺失按"待核对"处理（宁缺勿错）；
3. `status=待核对` 的条目**不得参与计算结论**：加载器 `effective_ruleset()` 统一门控（"无出处数值不得生效"红线的代码化）；
4. 金额/税率统一 Decimal 语义；税率字段为字符串（如 `"0.03"`）；
5. 税率表固定 7 级、区间相接、末级上不封顶（`upper: null`）；
6. 综合所得年度表逐行另挂 `ref_qd`：速算扣除数出处 = 61号公告附件《个人所得税预扣率表一》（个税法税率表一原文不含速算扣除数列）；
7. 修改规则包必须跑 `python -m pytest`（schema、门控与位级一致测试会同步验证）。

## 复核元数据（`review` 块与 `sources[].reviewed_at`）

每份规则包顶层带 `review` 块，来源逐条带 `reviewed_at`：

```json
"review": {
  "reviewed_at": "2026-10-07",
  "next_review": "2027-01-31",
  "basis_year": 2023,
  "carry_forward_years": [2024, 2025, 2026],
  "scope_note": "2023 官方原文逐字核对；2024-2026 沿用 2023 标准，未取得逐年度新文件"
}
```

- 2019-2021：`basis_year=2019`，`carry_forward_years=[2020,2021]`；
- 2022：`basis_year=2022`，`carry_forward_years=[]`（含婴幼儿照护设立）；
- 2023-2026：`basis_year=2023`，`carry_forward_years=[2024,2025,2026]`。

**口径说明**：2024-2026 **沿用 2023 标准，不是逐年复核**；仓库最新原文快照为 2023-08，没有 2024/2025/2026 的逐年度新文件。取得官方原文后再更新日期与 `scope_note`。年终奖单独计税（公告2023年第30号）执行至 **2027-12-31**，`next_review=2027-01-31` 用于在该边界前确认政策是否延续。
