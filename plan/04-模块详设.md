# 04 模块详设

> 定稿日期：2026-10-07。本文是模块级设计定稿：规则包 schema、四个引擎模块、依据联动、错误处理。
> **数值纪律**：文中引用的税率/扣除标准仅用于说明 schema 结构与算法形态，入库生效值以 [data/rules/](../data/rules/) 内挂原文核对后的条目为准（status 门控）。

## 一、年度规则包 schema（v1）

文件：`data/rules/ruleset-YYYY.json`。所有金额字段 Decimal 语义（JSON 里写成数字，加载时 `parse_float=Decimal`）；所有**数值条目**必带 `ref`（文号+条款）与 `status`（`已核对`/`待核对`）。

```jsonc

    {"id": "S61", "doc": "国家税务总局公告2018年第61号", "url": "", "status": "已核对"}
```

约束（schema 校验强制）：
- 税率表必须 7 级、`lower` 递增相接、`upper=null` 表最高级（或以数值+封顶标志表达）；
- 每个数值条目必有 `ref`；`status` 缺失视为 `待核对`（宁缺勿错）；
- `housing_loan_vs_rent` 必须显式存在且值为 `mutually_exclusive`（互斥规则不许省略）。

## 二、status 门控（rules/loader.py）

```
load_ruleset(year) -> Ruleset            # 结构加载：schema 校验 + 年份存在性；返回不可变 Ruleset
status_report(Ruleset) -> StatusReport   # 已核对/待核对计数与条目清单（CLI rules 命令渲染）
effective_ruleset(Ruleset) -> Ruleset    # 门控：存在待核对条目 → RulesetNotEffective（附清单）
```

- 引擎入口**只接受** `effective_ruleset()` 的产物——"未核对不得生效"红线的单点实现；
- `RulesetNotEffective` 携带待核对条目路径清单，CLI/GUI 原样呈现（免责纪律：告诉用户差哪些条目，而不是静默拒算）；
- 骨架期规则包多为待核对 → 上述 API 已可全链路测试；M1 核对完成后全绿。

## 三、引擎模块设计

统一约定：引擎函数输入 `(Ruleset, params dataclass)`，输出 `Report`（dataclass 树：每个叶子节点 = `value: Decimal` + `label` + `ref` 引用 + `note`）；纯函数、无 IO、无全局状态；金额运算全 Decimal，税率以 `Decimal` 字符串载入。

### 3.1 monthly.py — 累计预扣（FR-1，M2）

输入参数：12 个月序列（每月工资、当月专项扣除、当月专项附加扣除、当月其他扣除；社保联动模块的产出自动填充专项扣除字段）。

逐月状态机（61 号公告第六条公式逐字实现）：

```
对月份 m = 1..12：
  累计应纳税所得额[m] = Σ收入[1..m] − Σ免税收入 − 5000×m
                        − Σ专项扣除 − Σ专项附加扣除 − Σ其他扣除        # ← 逐项挂 ref
  累计应预扣税[m]     = 累计应纳税所得额[m] × 税率(查表) − 速算扣除数
  当月应预扣[m]       = 累计应预扣税[m] − Σ已预扣[1..m-1]              # 可为负？——按公告应为累计口径
  适用级次[m]         = 命中的税率表级（呈现用）
```

边界行为：累计应纳税所得额 ≤ 0 → 当月税额 0（不产生退税，负数不滚入下月抵扣——公告口径，M2 核对后在生成器注释里定稿）；月度输入缺失按 0 处理并标注。

### 3.2 bonus.py — 年终奖择优 + 临界区间（FR-2，M3）

**方案 A（单独计税）**：应纳税额 = 奖金 × 税率(奖金/12 查按月换算表) − 速算扣除数；政策有效期校验（申请年度 > 2027-12-31 → 该方案不可用，提示政策到期）。

**方案 B（并入综合）**：把奖金并入全年综合所得重跑年度汇算，比较两方案**全年总税负**（方案 B 与方案 A 的差额必须折算到同一年度口径），推荐总税负低者；两方案差 ≤ 0.01 元视为并列，输出"两案等同"。

**临界区间机制性推导**（不硬编码，评分亮点）：对按月换算表的每个级次边界 `b`（年口径 = 月口径×12，如 3000→36000）：

```
设在边界左侧级次 (r₁,q₁)、右侧级次 (r₂,q₂)，奖金净额 N(B) = B − (B·r − q)
边界右侧净额追平边界左侧净额的奖金值 B*：
    B* = ( b·(1−r₁) + q₁ − q₂ ) / (1 − r₂)
陷阱区间 = (b, B*)，区间内多发奖金 → 到手反而变少
```

验证锚点（推导自洽性，M4 边界扫描断言）：首区间 (36000, 38566.67)。区间端点由规则表推导生成——规则表变更自动跟随，**代码中不出现 38566.67 字面量**。

### 3.3 deductions.py — 七项专项附加（FR-3，M3）

每项扣除建模为 `Claim`（项目、分档选择、分摊比例、起止月份、金额），模块职责：

1. **标准计算**：按规则包标准值 × 数量/分档取值（子女教育/婴幼儿按孩数，租金按城市档）；
2. **互斥校验**：房贷利息与住房租金同时申报 → 拒绝并列出依据条款；
3. **分摊校验**：赡养老人非独生分摊额 ≤ 每人上限且合计 ≤ 总额；子女教育/婴幼儿分摊比例 ∈ {100%/一方， 50%/50%}；
4. **阶段标注**：大病医疗 `stage=settlement_only` → 预扣链自动剔除、汇算链纳入（防止"逐月扣大病"错误）；
5. 输出逐项 `ClaimResult`（月额/年额 + ref），供 monthly / settlement 汇总。

### 3.4 social.py — 社保公积金联动（FR-4，M2）

输入：缴费基数（自动夹取到 [下限, 上限]）、养老/医疗/失业/公积金个人费率。输出：个人部分合计（Decimal）→ 直接作为 monthly 引擎的 `专项扣除 + 公积金` 输入（公积金个人部分计入专项扣除口径，M2 按公告口径核对后定稿），并回链"来自社保联动"标注。规则包不存社保数值（D-4）。

### 3.5 settlement.py — 年度汇算（FR-5，M2）

输入：全年工资薪金（或直接引用 monthly 结果）、年终奖方案选择、其他综合所得简化口径输入、已预缴合计。计算：

```
应纳税所得额 = 收入额合计 − 60000 − 专项扣除 − 专项附加扣除 − 其他扣除
应纳税额     = 查综合所得税率表
应退/应补    = 已预缴 − 应纳税额   （正=应退，负=应补）
```

每个数值挂汇算依据（个税法 + 61 号/30 号相关条款 ref）。

## 四、基准评测（benchmark/，FR-7，M4）

| 基准 | 方法 | 达标线 |
|---|---|---|
| 算例回归 | `data/truth/` 真值 JSON（61 号公告算例 + 官方问答案例，逐条登记来源 URL）vs 引擎输出，全字段对账 | 通过率 100% |
| 税率级次临界 | 程序化枚举税率表每个 `upper` 边界 ±ε（Decimal 精确邻域），断言级次切换与税额连续性/跳变符合机制 | 与规则表 100% 自洽 |
| 年终奖陷阱区间 | 枚举每个推导区间端点内外 ±0.01 元，断言"区间内到手变少、区间外恢复" | 推导区间与穷举最劣点 100% 一致 |
| 扣除互斥组合 | 房贷+租金等互斥/分摊边界组合枚举 | 拒绝率 100%，误放行 0 |

零 API 依赖、纯规则通路、固定 seed（如需随机输入）可重复；指标进 README。

## 五、错误处理与退出码（定稿，锁进 CLI 测试）

| 情形 | 行为 | 退出码 |
|---|---|---|
| 成功 | 输出结果/报告 | 0 |
| 引擎未实现（骨架期 `calc`）、计算期失败、status 门控拦截 | stderr 明示原因（门控附待核对清单） | 1 |
| 参数错误、年份无规则包文件、schema 非法 | stderr 明示原因 + 用法提示 | 2 |
