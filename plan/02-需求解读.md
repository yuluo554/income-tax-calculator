# 02 需求解读

> 来源：[01-题目详细定义.md](01-题目详细定义.md)。本文把题目痛点转译为系统能力，固化 FR 功能清单（带优先级与评分映射）与边界非目标。
> 定稿日期：2026-10-07

## 一、痛点 → 能力转译

| # | 用户痛点 | 系统能力 | 对应 FR |
|---|---|---|---|
| P1 | 网页计算器广告缠绕、计算过程不透明 | 桌面全本地程序，逐月计算过程完整呈现（累计口径逐月明细表） | FR-1/FR-8 |
| P2 | 工具不给政策依据，结论无从核对 | 每个结果数值旁挂政策文号+条款依据，界面"依据面板"可展开 | FR-14（依据联动） |
| P3 | 政策年度间变化（2023 三项提标、年终奖政策延续至 2027 底），旧工具结论过时 | 年度版本化规则集 2019-2026，切换年度即切换规则；未挂原文核对的条目不得生效 | FR-6 |
| P4 | 年终奖"多发一元、到手变少"，没人讲清临界区间在哪 | 双计税方案对比自动择优 + 临界区间由税率表机制性推导生成并标红 | FR-2 |
| P5 | 专项附加扣除规则复杂（分档/互斥/分摊），不知道自己能扣多少 | 七项扣除规则化管理：分档、房贷租金互斥、赡养分摊上限校验 | FR-3 |
| P6 | 社保公积金个人部分手工算错、与税前扣除脱节 | 基数上下限+费率输入 → 个人部分自动进入税前扣除链 | FR-4 |
| P7 | 汇算季不知道补税还是退税 | 年度汇算：应纳税额 vs 已预缴 → 应退/应补，附依据 | FR-5 |
| P8 | 无从判断计算器本身算得对不对 | 内置评测基准：官方算例真值 100% 通过 + 边界扫描自洽，零 API 可复现，指标进 README | FR-7 |

## 二、FR 功能清单

优先级：P0=首期必须（评分主干），P1=应有，P2=扩展。评分映射见 01 §四。

| FR | 名称 | 内容 | 优先级 | 评分映射 |
|---|---|---|---|---|
| FR-1 | 累计预扣法逐月引擎 | 按税务总局公告 2018 年第 61 号公式逐字实现：累计应纳税所得额 = 累计收入 − 累计免税收入 − 累计减除费用（5000×月份数）− 累计专项扣除 − 累计专项附加扣除 − 累计其他扣除；输出逐月应预扣税额、累计应纳税所得额、适用预扣率级次 | P0 | 功能 40 / 完整性 20 |
| FR-2 | 年终奖择优引擎 | 单独计税（÷12 查按月换算税率表）vs 并入综合所得，双方案对比自动推荐；**临界区间由规则集税率表机制性推导**（不硬编码），结果标红提示 | P0 | 功能 40 / 创新 20 |
| FR-3 | 七项专项附加扣除管理 | 子女教育/继续教育/大病医疗/房贷利息/住房租金/赡养老人/婴幼儿照护；分档标准、租金与房贷**互斥**、赡养独生定额 vs 非独生分摊上限、大病医疗限额等规则化校验 | P0 | 完整性 20 |
| FR-4 | 社保公积金联动 | 缴费基数上下限、个人费率（养老/医疗/失业/公积金）输入 → 个人部分计算并自动进入税前扣除链 | P0 | 完整性 20 |
| FR-5 | 年度汇算 | 全年综合所得汇总 → 应纳税额 vs 已预缴 → 应退/应补税额，附汇算依据；劳务报酬/稿酬/特许权使用费按简化口径（决策：首期以工资薪金+年终奖为主，其他所得类型留输入位） | P0 | 功能 40 |
| FR-6 | 年度版本化规则集 | 2019-2026 规则包 JSON：减除费用、综合所得税率表、按月换算税率表、专项附加标准、年终奖政策有效期；切换年度即切换规则；每条挂文号+status，**status≠已核对不得生效** | P0 | 创新 20 |
| FR-7 | 内置评测基准 | ①官方/权威口径算例真值（61 号公告算例、税务官方问答，逐条登记来源）通过率 100%；②边界扫描：税率级次临界点、年终奖陷阱区间边界、扣除互斥组合枚举自洽；零 API 依赖可重复，指标进 README | P0 | 功能 40 / 创新 20 |
| FR-8 | 桌面 GUI | PySide6：年度切换、逐月明细表、年终奖双方案对比+临界警示、扣除项管理页、依据面板、免责声明展示 | P0 | 完整性 20 / 表现力 20 |
| FR-9 | exe 打包与 Release | PyInstaller 打包 Windows exe，GitHub Release 附安装包 + 演示 GIF/截图 | P0 | 表现力 20 |
| FR-10 | 依据联动机制 | 规则包每条数值条目携带 source{文号,条款,URL?,核对日期}；引擎输出的每个税额/扣除额回链对应条目 | P0 | 创新 20 |
| FR-11 | 免责声明强制 | 应用启动/结果页强制展示：计算结果供参考，以税务机关核定为准；政策以发文机关正式文本为准 | P0 | 合规红线 |
| FR-12 | 全本地零上传 | 无网络请求、无遥测、无数据出本机（合规红线，CI/测试可断言） | P0 | 合规红线 |
| FR-13 | CI | GitHub Actions：多版本 Python 矩阵跑全量测试 + 基准 | P1 | 表现力 20 |
| FR-14 | 技术报告 | 规则集版本化设计、临界区间推导、依据联动机制三大主题 | P1 | 表现力 20 |
| FR-15 | CLI 通路 | 无 GUI 的命令行通路（打包场景脚本化验证、CI 评测入口） | P1 | 工程 |

## 三、边界与非目标

**不做**（扩展项，留接口不做实现）：
- 经营所得、股权激励、财产租赁/转让等复杂所得类型；
- 劳务报酬/稿酬/特许权使用费的完整口径（首期仅汇算简化口径留输入位，见决策记录 2026-10-07）；
- 对接税务局接口、申报代办；
- 避税建议（临界区间提示仅为**机制性事实呈现**，不构成筹划建议）；
- 多币种、港澳台/外籍个人税收协定场景。

**合规红线**（违者即缺陷）：
- 全本地计算存储、零上传、零外链；
- 免责声明强制展示（FR-11）；
- 规则包条目未挂原文核对（status=待核对）不得生效参与计算结论；
- 无来源数值不得作为基准真值。

**数据纪律**：算例真值逐条登记来源（公告条文/官方问答 URL）；边界扫描用例由程序从规则表推导生成并与规则表自洽对账。

**品牌隔离**：不复制姊妹项目代码；文档不提其余项目业务领域（plan/00 系列清单仅作内部导航，发布前复核）。
